# 连接地址规则与预设地址

本文说明登录页「服务器地址」的校验/归一化规则，以及预设地址的保存逻辑。
对应实现：`data/api/ServerAddressRules.kt`、`data/ServerPreset.kt`、`ui/login/`。

## 1. 地址校验与归一化

登录只接受两类地址，走**同一套**解析流程，区别仅在类型标签与自动命名：

| 类型 | 示例 | 判定依据 |
| --- | --- | --- |
| IP 地址 | `192.168.1.10:8655`、`http://192.168.1.10:8655` | 主机是 IPv4 字面量（每段 ≤ 255）或含 `:` 的 IPv6 字面量 |
| URL 地址 | `https://app-demo.example.com/`、`https://example.com/javboss/` | 主机是域名 |

处理顺序（`ServerAddressRules.resolve`）：

1. 去掉首尾空白；空串、内部含空白/换行、超过 300 字符 → 直接拒绝。
2. **不含 `://` 时自动补 `http://`**（与旧版一致，`192.168.1.10:8655` 老写法继续可用）。
   无协议头的域名同样补 `http://`，因此 **https 隧道必须显式写 `https://`**。
3. 协议只允许 `http` / `https`；`ftp://`、`ws://` 等拒绝，并提示只支持 http/https。
4. 交给 OkHttp 解析：主机名非法、端口越界（1–65535）、编码错误 → 解析失败即拒绝。
5. 拒绝携带用户名/密码的地址（`http://user:pass@host`），避免同源判定被绕过。
6. 归一化：丢弃 `?query` 与 `#fragment`，去掉末尾斜杠，省略协议默认端口（http:80 / https:443），
   路径前缀保留（`https://example.com/javboss/` → `https://example.com/javboss`）。
7. 归一化结果同时用于：Retrofit baseUrl、`AuthProxy` 转发、会话 Cookie 同源校验
   （`ServerOrigin` 比较 scheme + host + port，路径前缀不参与比较）。

输入过程中的提示（不阻断输入）：

- 非法 → 输入框标红，下方显示「地址有误：<具体原因>」。
- 合法但会被改写 → 显示「将使用 <归一化地址>」，让用户看到实际会连接的地址。
- 合法且无需改写 → 显示「已识别为 IP 地址 / URL 地址」。

旧数据兼容：`SessionManager.restore()` 会用同一套规则重新归一化已保存的地址并回写，
旧版本遗留的 `http://host:port/` 会变成 `http://host:port`，不影响原有连接。

## 2. 预设地址

### 数据结构

```kotlin
data class ServerPreset(
    val name: String,      // 展示名，1–40 字
    val url: String,       // 归一化地址，同时作为去重主键（无独立 id）
    val password: String,  // 保存的密码；空串 = 没存，点选后需手输
    val addedAt: Long,     // 首次添加时间
    val usedAt: Long,      // 最近使用时间，决定排序
)
```

### 去重

- 键 = 归一化 url（`PresetRules.keyOf`）。因此 `192.168.1.10:8655`、
  `http://192.168.1.10:8655/`、`HTTP://192.168.1.10:8655` 视为**同一条**。
- 同址再次保存/再次登录成功 → 不新增，只更新 `usedAt` 并移到列表首位；
  `addedAt` 与已有名称保持不变（除非用户显式填了新名称）。
- 解析失败的地址不会被保存（返回原列表）。

### 命名

- 用户显式填写的名称优先：合并连续空白、截断到 40 字；
- 名称为空 → 自动命名：私有网段 IP 为 `局域网 <host:port>`（10/8、172.16–31、192.168/16、127、169.254），
  其它为 `<host[:port]>`；
- 名称允许重复（身份是 url 不是名称），但列表同时展示 url 以便区分。

### 排序与容量

- 列表顺序即展示顺序，最近使用（`usedAt` 最大）在最前；
- 上限 20 条，超出时淘汰最久未使用的一条（`PresetRules.MAX_PRESETS`）。

### 持久化

- DataStore Preferences，文件名 `server_presets`，单个 key `presets_json` 存整段 JSON 数组；
- 每次增删改都整表覆盖写入（原子写，不会半截损坏），启动时 `AppContainer.presets.restore()` 读回；
- JSON 损坏或版本不兼容时回退为空列表，不影响登录；
- 密码与预设同存于该 JSON（`android:allowBackup="false"`，不进系统/云备份）；Cookie 仍由 `SessionManager` 单独保存。
- 与原版共用同一套代码路径但 applicationId 不同，因此预设数据与原版应用互不干扰；
  v0.3.47 起包名改为 `com.javboss.modified`，与旧 `com.javboss.phone.preset` 同样是不同包，
  DataStore 不迁移，换包后需重新录入两条登录预设。

### 密码与自动登录

| 场景 | 行为 |
| --- | --- |
| 「记住密码」开启（默认） | 登录成功后把该地址的密码写进预设，下次点预设直接登录 |
| 「记住密码」关闭 + 手输登录 | 成功的同时清掉该地址已存的密码 |
| 「记住密码」关闭 + 点预设登录 | 不动已存密码（避免误解锁后顺手抹掉） |
| 点无密码的预设 | 只填地址与清空密码框，等用户输入 |
| 预设密码被服务端拒绝（401） | 提示「预设里保存的密码已失效」，并清掉该预设的密码，避免反复撞同一个错 |

- 合并语义：`PresetRules.upsert(..., password = null)` 保留原密码，传 `""` 表示清空；
  只改名（`rename`）不会影响密码。
- 列表项右侧出现 🔒 即表示该预设已存密码、可一键登录。

## 3. 界面入口

| 入口 | 位置 | 行为 |
| --- | --- | --- |
| 保存为预设 | 地址输入框右侧 ★ 按钮 | 先校验，合法则弹「保存为预设」对话框，名称预填自动名；地址已存在时提示将更新并置顶 |
| 选择预设 | 「预设地址（N）」列表项点按 | 已存密码 → 立刻登录；没存密码 → 只填入地址并清空密码框 |
| 管理入口 | 预设列表标题右侧「管理 / 完成」 | 切换到管理模式，每项右侧出现重命名 ✎ 与删除 🗑 |
| 记住密码 | 密码框下方开关（默认开） | 决定登录成功后是否把密码写进预设 |
| 自动收录 | 登录成功 | 当前地址自动写入预设并置顶，无需手动保存 |

空列表时预设区块整体隐藏，不占纵向空间；登录页整体可滚动，预设较多时不影响密码与登录按钮可达性。
